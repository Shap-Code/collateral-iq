# 03 - Instructions

**Time:** 25 minutes
**You will learn:** how to make Copilot learn our vocabulary and rules once
**You will need:** lesson 03 finished

## The problem instructions solve

Ask a fresh Copilot to "add a comp" and it may produce a function that accepts an
active listing, invents an adjustment rate, and returns a float with no audit
trail. None of that is unreasonable for a generic assistant. It is wrong for us.

You could explain our rules at the top of every chat. Instructions files mean you
explain them once, in the repository, and they load automatically for everyone
who clones it.

## The two kinds

**Repository-wide:** `.github/copilot-instructions.md`
Loads into every Copilot chat in this repository, no matter what file you are in.
Open ours and read it now. Notice what is in there: our domain vocabulary, the
standard-library-only rule, the rule that adjustment rates live in exactly one
place, and what to refuse.

**Scoped by file type:** `.github/instructions/*.instructions.md`
Loads only when the files being worked on match a glob pattern in the YAML
frontmatter at the top of the file.

```markdown
---
applyTo: "**/*.py"
description: Python conventions for Collateral IQ.
---
```

We have two: `python.instructions.md` and `docs.instructions.md`. The Python one
says things that would be noise in a Markdown file - type hints, no bare except,
no printing from library modules. The docs one says the opposite kind of thing -
lesson structure, no screenshots without alt text, do not use the word "simply".

## See it working

Ask Copilot, with the chat open on any Python file:

> Write a function that returns the average sale price of the comps for SUBJ-003.

Look at what comes back. It should use the loader rather than opening the CSV
itself, use stdlib only, avoid printing from inside `src/`, and use our words -
"comps", not "properties". If it does any of that without you asking, that is the
instructions file doing its job.

Now check the reverse. In the chat, ask:

> What rules are you following in this repository?

Copilot should be able to summarise them back to you.

## Write one

Add a third instructions file for the CSV data. Create
`.github/instructions/data.instructions.md`:

```markdown
---
applyTo: "data/*.csv"
description: Rules for the sample datasets.
---

# Sample data rules

- All rows are synthetic. Never add a row that describes a real property, a real
  APN, or a real borrower.
- Do not hand-edit these files. They are generated by `tools/generate_data.py`;
  change the generator and rerun it, so the data stays reproducible.
- Prices are whole dollars. Square footage is above-grade living area only.
- If you add a column, add it to the coercion sets in `loader.py` in the same
  change, or it will silently load as a string.
```

Save it, then in chat ask Copilot to add a column to `comps.csv`. It should push
back and point you at the generator.

## How to tell a good instruction from a bad one

A good instruction is a rule that a competent newcomer could not have guessed,
and that has a consequence when broken. "Use clear variable names" is noise -
every assistant already tries to. "Adjustment rates live only in `ADJUSTMENTS`,
because a rate in two places will eventually disagree with itself" is a real
rule with a real reason.

Keep the file short. An instructions file nobody reads is one nobody maintains,
and Copilot weighs a focused file more reliably than a sprawling one.
